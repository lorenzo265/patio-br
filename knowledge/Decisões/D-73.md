# D-73

**Decisão:** **A produção e a homologação por dentro** ([[T49]]): a imagem `patio-nuvem` no registro do GitHub, com o resumo do commit como versão; o compose de `infra/producao/` com as migrações num serviço que roda uma vez e termina antes de a API subir, a API, o worker e o Caddy (só ele com portas abertas); a homologação usa o mesmo compose com o PostgreSQL num contêiner (um perfil a mais); o deploy pela Tailscale SSH, com a etiqueta do GitHub Actions na rede da Tailscale; a etiqueta `nuvem-v*` vai para a produção pelo ambiente "producao" do GitHub, que pede a aprovação; os segredos num `.env` da máquina, só do dono

**Motivo:** a mesma imagem e o mesmo compose nos dois ambientes; a migração antes da API, e não dentro dela, não deixa duas réplicas migrarem juntas; a Tailscale SSH não precisa de chave guardada nem de porta aberta ([[D-13]]); a aprovação do ambiente é do próprio GitHub, sem ferramenta a mais

**Alternativa descartada:** migrar dentro da API ao subir; a chave SSH nos segredos do GitHub com a porta 22 aberta; um orquestrador (Kubernetes, ECS) para duas máquinas
