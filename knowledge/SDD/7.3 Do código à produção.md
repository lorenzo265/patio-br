# 7.3 Do código à produção

1. Cada envio ao GitHub roda ruff, mypy, pytest e checagem de licenças.
2. Imagens Docker vão para o registro privado do GitHub.
3. `main` → homologação automaticamente. Tag de versão → produção.
4. Segredos ficam nos "secrets" do GitHub e do servidor. Nunca no repositório.

Por dentro ([[D-73]]): a imagem da nuvem (`patio-nuvem`) leva o resumo do commit; cada máquina tem o
compose de `infra/producao/` (as migrações, que rodam uma vez antes de a API subir, a API, o
worker e o Caddy, o único com portas abertas, 80 e 443); a homologação acrescenta o PostgreSQL num
contêiner. O deploy entra na máquina pela Tailscale SSH, sem chave guardada no GitHub e sem a
porta do SSH aberta na internet: troca a versão da imagem no `.env` da máquina, baixa e sobe. A
etiqueta `nuvem-v<versão>` vai para a produção só com a aprovação do Lorenzo no ambiente
"producao" do GitHub.
